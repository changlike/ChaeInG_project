## 1. 해야 할 일 (순서대로)

### A. CSV 성분표 수정 5건 ← 사용자가 직접
`load_products`가 자동 분리가 위험하다고 판단해 **적재에서 제외**한 제품들. 올리브영 상품 페이지의 "성분보기"를 보고 수정.

| CSV 행 | 제품 | 문제 | 수정 방향 |
|---|---|---|---|
| 7 | 히알루 B5 수분탄력 세럼 | `[히알루 세럼] … [히알루 크림] …` 세트 처방이 한 칸에 섞임 | 이 제품에 해당하는 처방만 남기고 `[ ]` 제거 (제품명상 세럼 쪽으로 보이나 상품 페이지에서 확인) |
| 25 | 어성초 77 히알루론산 수분 진정 토너 | `[크림]` 표기가 섞임 | 토너 처방만 남김 |
| 11 | 레티놀 시카 모공 흔적 앰플 | 성분 사이에 `*3X RETINOL COMPLEX 1% : …` 설명 | 설명 문구 제거, 성분만 남김 |
| 15 | 피디알엔 히알루론산 캡슐 100 세럼 | `* 피디알엔: …` 주석 | 주석 제거 |
| 50 | DMT 페이셜 크림 | `:` 포함 주석 | 주석 제거 |

- 제외 판정 규칙: 성분표에 `[` `]` 또는 `:`가 있으면 제외 (`review_reason`)
- **63행**은 49행과 같은 제품·같은 URL인 진짜 중복 → CSV에서 삭제 가능
- 수정 후 확인 (기대: 경고 0건, 제품 104개)
  ```bash
  cd backend
  python -m scripts.load_products --dry-run
  python -m scripts.load_products
  python -m scripts.tag_concerns          # 초안 CSV 재생성
  ```

### B. 성분→고민 사전 검수 ← 사용자 (논의 포함)
파일: `data/ingredient_concern_map.csv` (컬럼: `ingredient_name, concern, strength, position_rule, basis`)

검수 시 볼 것:
1. **고민 매핑이 맞는가** (예: 병풀 계열을 여드름/트러블과 홍조 둘 다에 weak로 넣음)
2. **strong/weak 구분이 적절한가** (strong은 1개만 있어도 고민 후보가 됨)
3. **`top_n` / `any` 구분이 적절한가** (`any`는 위치와 무관하게 인정 → 소량 유효 성분용)
4. **기능성 고시 성분 여부 원문 확인** — `basis`에 "(원문 확인 필요)"라고 적은 행들
   - 확인 대상: 나이아신아마이드, 알파-알부틴, 3-O-에틸아스코빅애씨드, 아스코빌글루코사이드, 소듐아스코빌포스페이트, 트라넥사믹애씨드, 아데노신
   - 출처: 식약처 「기능성화장품 심사에 관한 규정」·고시 성분 목록 (2025-12-16 개정본 기준으로 확인할 것)
5. **펩타이드류** 효능 근거 수준이 낮을 수 있음 → strong으로 둘지 weak으로 낮출지 결정
6. **누락 성분 추가**: 특히 모공(피지·각질 관련), 홍조, 여드름/트러블 사전이 빈약함

### C. 점수 부풀림 보정 ← 논의 후 코드 수정
문제: 같은 계열 성분(히알루론산 변형 10종 등)이 각각 strong 2점으로 계산되어 건조/보습이 부풀려짐.

| 현재 결과 (제품당 상위 2개 적용, 99개) | |
|---|---|
| 건조/보습 | 83개 (1순위 68개) |
| 주름/탄력 | 30 |
| 미백/톤 | 22 |
| 홍조 | 18 |
| 여드름/트러블 | 9 |
| 모공 | 1 |
| 판정 없음 | 4 |
| 건조/보습 점수 중앙값 6 vs 그 외 고민 최고점 중앙값 3 | |

제안: 사전에 `family` 열 추가 → **같은 계열은 점수 1회만 반영** (히알루론산, 병풀, 펩타이드, 비타민C 유도체 등). 적용 후 분포를 다시 확인.

### D. 검수 확정값 DB 반영 ← 코드 작성 필요 (아직 없음)
1. `data/main_concerns_draft.csv`의 `verified_concerns` 칸에 사람이 확정한 고민을 채움 (콤마 구분), `reviewed`에 표시
2. 확정된 행만 `products.main_concerns`에 쓰고 `is_concerns_verified = True`
3. 스코어링 엔진은 `True`인 제품만 사용
- 반영 스크립트(예: `scripts/apply_concerns.py`)는 **미작성**. 6개 고민 어휘 검증 포함해서 작성 예정

## 2. 논의가 필요한 것 (결정 대기)

| # | 주제 | 현재 | 선택지 / 의견 |
|---|---|---|---|
| 1 | `TOP_N` (함량 의존 성분 인정 범위) | 20 | 보존제 첫 등장 위치 중앙값이 18, 하위 25%가 13이라 20은 경계 부근. 결과를 보고 12~20 사이에서 조정 |
| 2 | 제품당 주력 고민 개수 | 최대 2 | 3으로 늘리면 쏠림은 덜하지만 "주력"의 의미가 약해짐 |
| 3 | 후보 조건 | strong 1개 또는 weak 2개 | weak 임계값을 3으로 올릴지 |
| 4 | 동점 처리 | 근거 성분이 앞쪽인 고민 우선 → 그다음 고민 순서 | 고민 순서 대신 다른 기준이 나은지 |
| 5 | 판정 없음 4개 제품 | 고민 없음으로 저장 | 수기 태깅할지, 비워 둘지 |
| 6 | CSV `확인` 컬럼 (o/O) | **데이터 확인 표시로 해석**, 사용 안 함 | 의미가 다르면 알려 주기 (주력 고민 검수 표시라면 사용 방식이 달라짐) |
| 7 | `skin_type_target` | 101/105가 "모든 피부" | 결정: 자체 판단 값을 성분 기반으로 분리해 **가산점**으로 사용. 컬럼·사전 설계는 미정 (고민 사전과 같은 방식 적용 가능) |
| 8 | 성분 효능/주의사항 | 공공 API 못 찾음 | 소수 핵심 성분부터 수기 정리 + LLM 초안(검수 전 표기) |
| 9 | 선크림·클렌저 | 데이터 없음 (현재 5개 카테고리) | 범위에 포함할지, 데이터를 추가 수집할지 |
| 10 | 사전 검수를 누가 어떻게 | 사용자 검수 | 사전이 커지면 `verified` 열을 추가해 행 단위 검수 표시 |

## 5. 작업 시 주의

- CSV는 **한 곳에서 수정 → 커밋·푸시 → 다른 곳에서 `git pull`** 순서를 지킬 것 (두 PC에서 동시에 고치면 충돌)
- 엑셀로 저장하면 "CSV UTF-8"로 저장할 것 (인코딩이 깨지면 한글이 깨짐)
- `data/main_concerns_draft.csv`는 생성물이므로, `tag_concerns`를 다시 돌리면 **검수 칸(`verified_concerns`, `reviewed`)이 지워짐**. 검수를 시작한 뒤에는 재생성하지 말거나, 먼저 다른 이름으로 복사해 둘 것
- `.env`는 열어 보지 않는다 (CLAUDE.md 지침)
