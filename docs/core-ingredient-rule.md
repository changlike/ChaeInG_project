# 핵심 성분 판정 규칙 (제품별 경계 + 제품명 신호)

> 상태: **기획안 (방향 확정, 구현 전)** / 작성: 2026-11-19
> 목적: 제품의 "주력 고민"(`main_concerns`)을 만들 때, 어떤 성분을 "이 제품의 핵심"으로 인정할지 기준을 다시 세운다.

---

## 1. 왜 다시 세우는가

현재 규칙은 성분 사전에 `position_rule`(`top_n` / `any`)을 두고, 고정값 `TOP_N = 20`으로 "앞 20번째까지만 인정"한다. 점검 결과 이 기준은 근거가 약하다.

| 문제 | 내용 |
|---|---|
| 20의 근거가 불확실 | 기존 문서의 "보존제 첫 위치 중앙값 18"은 재현되지 않음. 재계산하면 기준에 따라 6, 15, 19로 달라지고 계산 방식도 확인할 수 없음 |
| 경계가 제품마다 크게 다름 | 1% 이하 성분 마커의 첫 위치가 **1~76번째**로 흩어져 있음 (아래 표). 고정 20은 어떤 제품엔 너무 넓고 어떤 제품엔 너무 좁음 |
| 있다 ≠ 핵심 | `any` 규칙은 극소량만 들어 있어도 고민이 붙음. 반대로 함량이 적어도 제품이 내세우는 핵심 성분은 놓칠 수 있음 |

성분표 표기 규칙: **1% 초과 성분은 함량 많은 순서**, **1% 이하 성분은 순서가 함량과 무관**하다. 따라서 "순서를 믿을 수 있는 구간"은 제품마다 다르다.

### 현황 측정 (104개 제품 기준, 2026-11-19 — 이후 데이터는 100개로 정리됨)

| 마커 기준 | 마커를 찾은 제품 | 경계 위치 범위 | 중앙값 |
|---|---|---|---|
| 엄격: 페녹시에탄올·파라벤류·클로페네신·소듐벤조에이트·포타슘소르베이트·에틸헥실글리세린 | 68개 (36개는 없음) | 7~57 | 19 |
| 넓게: 엄격 + 향료·카보머·잔탄검·이디티에이·구연산·소듐시트레이트·소듐하이드록사이드·아르기닌·색소 | 97개 (7개는 없음) | 1~76 | 15 |

- 이 데이터의 제품은 보존제로 페녹시에탄올을 거의 쓰지 않음 (104개 중 3개). 1,2-헥산다이올(83개)은 보습제로 1% 넘게 쓰일 수 있어 **마커에서 제외**
- 성분 수 중앙값은 33개

## 2. 새 규칙

```
핵심 성분 인정 = ① 그 제품의 경계 앞에 있다
              또는 ② 경계 뒤(소량)에 있지만 제품명에 그 성분이 언급된다
```

### 2-1. 제품별 경계 (C안)
- **경계 = 그 제품에서 처음 나오는 "1% 이하 마커 성분"의 위치**
- 마커가 1% 이하 영역 어디에든 있을 수 있으므로, 이 위치는 실제 1% 경계의 **상한**이다
  - 경계 **뒤**에 있는 성분은 **확실히 소량**이다 → 이 쪽은 근거가 확실
  - 경계 **앞**에 있는 성분은 1%를 넘을 수도, 아닐 수도 있다 → 순서를 믿고 인정하되 "가능성"으로 취급
- 마커는 **넓은 기준**을 사용 (여러 종류의 마커를 쓸수록 상한이 촘촘해짐)
- 마커가 없는 제품(현재 약 7개)은 **대체 경계 = 성분 수의 절반 정도**로 계산한다 (확정). 성분이 많은 제품은 경계도 뒤로 가는 점을 반영하는 방식이며, 비율 자체는 임의로 정한 기준이다(참고: 마커가 있는 제품의 경계 위치 ÷ 전체 성분 수 중앙값은 약 0.55). 결과에는 "경계 추정"으로 표시한다

### 2-2. 제품명 신호 (B안, 메인)
- 제조사가 핵심으로 내세운 성분은 **제품명에 적혀 있다.** 예: "히알루론산 세럼", "TXA 나이아신 흔적 세럼", "레티놀 시카 모공 흔적 앰플", "징크테카 트러블 세럼"
- 104개 중 65개(약 63%)의 제품명에 성분 또는 고민 키워드가 있음
- 경계 뒤(소량)에 있는 성분이라도 **제품명에 언급되면 핵심으로 인정**한다. 함량이 적어도 제품의 핵심인 경우(예: 뒤쪽 히알루론산, 레티놀)를 구제하는 장치
- 제품명의 표현과 성분표의 표기가 다르므로 **별칭 표**가 필요 (아래 4장)
- 제품명에 성분이 없고 경계 앞 근거도 약한 제품은 **"근거 부족"** 으로 표시한다 (억지로 고민을 붙이지 않음)

### 2-3. 기존 사전과의 관계
- `position_rule`(`top_n`/`any`) 구분은 이 규칙 하나로 **대체**된다 (사전에서 열 삭제 또는 무시)
- strong/weak, 계열(family) 1회 반영, 상위 2개 선택 규칙은 **유지**
- 자극 성분 게이트(`irritant_ingredients.csv`) 기준 (확정): 알코올류(`top_n`)는 **제품별 경계 앞이면 탈락, 경계 뒤(소량 확실)면 탈락시키지 않고 "소량 함유" 경고만 표시**한다. 향료·알레르기 유발 성분·에센셜 오일(`any`)은 지금처럼 **위치와 무관하게 탈락**. 경계를 추정한 제품(마커 없음)은 안전 쪽으로 보수적으로 판정하는 방식은 구현 시 확인

### 2-4. 두 겹 구조: 함유 / 주력 (방향 확정, 세부 미정)
- 들어 있는 성분의 **기능은 위치와 무관하게 기록**한다 (= **함유**). 있는 성분을 없다고 하지 않는다
- **주력**은 위 2-1, 2-2의 규칙(경계 앞 또는 제품명 언급)으로 정한다
- 용도 분리: "00 성분 빼고" 같은 요구는 **함유 여부**로 거르고, 고민 매칭 순위는 **주력**으로 정한다. 카드에는 "미백이 주력은 아니지만 나이아신아마이드가 소량 함유" 같은 표시가 가능
- **아직 정하지 않은 것**: 함유 고민을 어떻게 저장할지(컬럼 추가 등), 한 제품 안에서 어느 기능이 더 핵심인지 가르는 방법, 점수 규칙(strong/weak, 제품명 신호 가중) — **성분 분류가 끝나고 데이터 분포를 본 뒤 결정**

### 2-5. 성분 분류 체계 (확정, 2026-11-19)
- **구조**: 성분 → **역할(기능 그룹)** → 6개 고민. 성분마다 "보습제", "진정 성분" 같은 역할은 출처로 확인할 수 있는 사실이므로 검수가 쉽다. 역할 → 고민 매핑은 설계자가 한 번만 정한다
- **역할 후보(초안, 분류하면서 조정)**: 기반/용제, 보존·점도·pH 등 처방 보조, 보습, 장벽, 에몰리언트/오일, 진정, 미백, 주름개선, 피지·각질, 항산화, 식물추출물
- **역할 → 고민 매핑(초안)**: 보습·장벽·에몰리언트 → 건조/보습 / 진정 → 홍조(여드름/트러블 포함 여부는 데이터를 보고 확정) / 미백 → 미백/톤 / 주름개선 → 주름/탄력 / 피지·각질 → 모공(여드름/트러블 포함 여부 미정)
- **고민 어휘 밖의 역할**: 항산화와 기반·처방 보조는 고민에 연결하지 않고 기록만 한다. 고민 어휘는 6개 그대로 유지한다
- **복수 역할**: 한 성분이 여러 역할을 하면 **모두 기록**하고 **대표 역할 1개**를 표시한다. 대표 역할이 주력 판정의 기준이 되고, 나머지 역할은 함유로 남는다
- **표시 요건**: 카드와 설명에는 대표 역할뿐 아니라 **부가 역할도 보여준다** (예: "보습 성분이 주력이고, 진정에도 쓰이는 성분이 함께 들어 있어요"). 효능을 단정하지 않고 출처로 확인한 역할만 표시한다

### 데이터 작업 순서 (확정)
1. 성분 분류 체계(기능 그룹) 확정 — 예: 기반/용제, 보존·점도, 보습, 진정, 미백, 주름, 피지·각질, 장벽, 식물추출물
2. 흔한 32개 성분부터 그룹 지정 (고유 성분 875개 중 20% 이상 제품에 등장). 출처와 함께 제시하고 사람은 출처 대조만 확인
3. 가끔·드문 활성 성분(약 374개)을 그룹별로 분류. 단일 제품에만 나오는 성분(469개)은 후순위, 식물추출물은 한 그룹으로 두거나 보류
4. 전 제품 분류 후 분포를 보고 점수 규칙 결정 → 구현 → 초안 재생성 → 100개 전수 검수

## 3. 마커 목록 (`data/dilution_markers.csv`, 신규 예정)

| 컬럼 | 설명 |
|---|---|
| `ingredient_name` | 마커 성분명 (부분 일치) |
| `group` | 보존제 / 향료 / 점도조절 / pH조절 / 킬레이트 / 색소 |
| `basis` | "통상 1% 이하로 사용"의 근거 |

- 보존제는 사용 한도가 1% 이하로 알려져 있으나, **이 세션에서 출처를 확인하지 못했다.** `basis`에 출처를 달고, 확인되지 않은 항목은 "가정"으로 표기한다
- 채영 님의 검수는 "이 성분이 통상 소량으로 쓰이는가"가 아니라 **"`basis`에 적힌 출처가 실제로 그렇게 말하는가"** 만 확인하는 방식 (성분 전문 지식 불필요)

## 4. 제품명 별칭 표 (`data/name_aliases.csv`, 신규 예정)

| 컬럼 | 예시 |
|---|---|
| `alias` | 나이아신, TXA, 시카, 테카, 히알루, 레티놀, 펩타이드 |
| `matches` | 연결되는 성분 또는 계열 (나이아신아마이드, 트라넥사믹애씨드, 병풀 계열, 히알루론산 계열 …) |

- 약 30개 예상. 사람이 "별칭 → 성분" 대응이 맞는지 확인 (조회 작업)
- 제품명의 **고민 단어**(수분, 진정, 미백, 모공 등) 처리 (확정): **성분 근거가 있을 때만 인정**한다. 제품명에 "수분"이 있고 해당 기능(보습) 성분이 실제로 들어 있을 때만 그 고민을 주력으로 인정하며, 마케팅 문구만으로는 고민을 붙이지 않는다 ("성분 기반" 원칙 유지)

## 5. 한계 (문서·README에 그대로 기록)
- 마커 위치는 1% 경계의 **상한**일 뿐 정확한 경계가 아니다
- 마커 목록과 별칭 표는 휴리스틱이며, 성분 전문가의 검수를 받지 않았다
- 제품명에 성분이 없는 제품(약 37%)은 경계 앞 근거에만 의존해 판정이 약하다
- 마커가 없는 제품은 대체 경계(성분 수의 절반 정도)를 쓰며, 이 비율은 임의 기준이다

## 7. 정정이 필요한 기존 기록 (구현 시 함께 수정)

`TOP_N`, `중앙값`, `position_rule`이 언급된 곳: `concern_tagger.py`(주석 포함), `recommender.py`, `scripts/tag_concerns.py`, `tests/test_concern_tagger.py`, `tests/test_recommender.py`, `docs/data-and-llm-policy.md`, `docs/data정제검수논의필요.md`, `docs/handoff.md`.
특히 "보존제 첫 등장 위치의 중앙값이 18" 이라는 서술은 재현되지 않으므로 삭제하거나 위 측정 결과로 대체한다.
