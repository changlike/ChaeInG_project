# ChaeInG PRD

## 1. 프로젝트 개요

- **프로젝트명**: ChaeInG
- **목표**: 사용자의 피부 타입과 원하는/피하고 싶은 성분을 기반으로 기초 스킨케어 제품을 추천하는 웹 서비스
- **핵심 가치**: 리뷰/인기순이 아닌 **화장품 성분 기반 추천**, 그리고 그 추천의 **판단 근거를 항상 명확히 보여줄 것**
- **개발 시작**: 2026-07-13
- **진행 상태**: 진행 중 (08-22~08-24경 자격증 시험으로 일시 중단 후 재개). 최초 계획(7주, ~08-31)보다 지연되고 있음 — 아래 8번 "진행 현황" 참고
- **개발 방식**: AI 에이전트와 협업, 설계를 먼저 함께 확정한 뒤 코드는 AI가 초안을 작성하고 사용자가 리뷰하며 이해하는 방식으로 진행 ("내가 모르는 구현이 하나도 없어야 한다" 원칙)

## 2. 프로젝트 범위

**포함**: 토너, 에센스, 세럼, 앰플, 로션, 크림, 선크림, 클렌저 (기초 스킨케어)

**제외**: 색조 화장품, 향수, 헤어 제품, 바디 제품

## 3. 주요 기능

| # | 기능 | 상태 (2026-10-15 기준) |
|---|---|---|
| 1 | 회원 기능 (회원가입/로그인/로그아웃) | 완료 |
| 2 | 피부 프로필 등록/조회/수정/삭제 | 완료 |
| 3 | 즐겨찾기 (찜하기/목록/취소) | 완료 |
| 4 | 화장품 검색 (제품명/브랜드/카테고리) | 완료 |
| 5 | 성분 검색 (성분명 검색 + 이 성분이 들어간 제품 역조회) | 완료. 단, 성분의 효능/주의사항 설명은 데이터 소스를 아직 못 찾아서 비어있음 |
| 6 | 추천 챗봇 (RAG) | 스코어링 엔진·추천 API·추천 화면 완료 (2026-10-24). 챗봇은 미착수 — 아래 참고 |

**추천 챗봇은 별도 "추천 폼" 페이지 없이, 챗봇 하나로 통합된 인터페이스로 설계함.** 사용자가 대화로 조건을 말하면 → 아래 4번 스코어링 엔진을 호출 → 그 결과를 자연어로 설명해서 답함. **LLM이 직접 추천을 판단하지 않고, 판단은 항상 Rule-Based 스코어링 로직이 하며 챗봇은 그 결과를 설명하는 역할만 함** (근거 있는 추천이라는 핵심 가치를 지키기 위함).

챗봇 자체는 두 갈래로 나뉨: ①성분 Q&A(FAISS 검색 기반 RAG), ②추천요청(스코어링 엔진 호출). 그 외 질문은 고정된 안내 문구로 응답. 자세한 라우팅/멀티턴 설계는 별도 문서화 예정.

## 4. 피부 프로필 항목

- **피부 타입** (5개 중 택1): 건성 / 지성 / 복합성 / 수부지 / 중성
- **민감성 여부**: 피부 타입과 **별도 축**으로 체크박스 처리 (민감성을 피부 타입의 한 종류로 넣지 않음 — 건성이면서 민감성인 경우 등을 표현하기 위함)
- **피부 고민** (6개 중 다중 선택): 여드름/트러블, 모공, 홍조, 건조/보습, 미백/톤, 주름/탄력
- **선호 성분 / 기피 성분**: 자유 텍스트 입력 (성분 종류가 너무 많아 고정 목록으로 만들지 않음)

이 6개 "피부 고민" 값은 제품 쪽 "주력 고민" 태그와 **동일한 어휘를 공유**함 (아래 5번 참고) — 사용자가 고른 고민과 제품에 태깅된 고민이 정확히 매칭되게 하기 위함.

## 5. 추천 방식 (스코어링 로직)

**Rule-Based 스코어링 시스템**. 단순 점수 합산이 아니라, **게이트(통과/탈락) + 가산점을 분리**한 구조로 설계함 — "피부타입이 안 맞아도 성분 점수가 높아서 추천되는" 것 같은 논리적 모순을 막기 위함. 안전/적합성 관련 항목은 감산이 아니라 하드 게이트로 처리.

### 1단계: 게이트 (통과/탈락만, 점수 없음)

| 항목 | 판정 기준 |
|---|---|
| 민감성 유발 성분 | 민감성 체크한 사용자 + 자극 유발 성분 포함 제품 → 탈락 |
| 기피/금지 성분 | 공공데이터(`REGULATE_TYPE = "금지"`) 기준 금지 성분 포함 → 탈락 |
| ~~피부 타입~~ | **v1에서는 미적용** — 실제 수집한 제품 데이터 기준 `skin_type_target`이 마케팅상 거의 전부 "모든 피부"로 되어있어(브랜드가 타깃을 넓히려는 목적), 게이트로 쓸 만큼 변별력이 없다고 판단해 일단 뺌. 나중에 성분 기반 추론 등 더 나은 신호가 생기면 추가 예정. 사용자 프로필의 피부 타입 자체는 계속 수집함 |

게이트 실패 시 최종 점수 0 처리 (임시 기본값, 추후 "비추천 섹션 + 경고 표시"로 개선 가능).

### 2단계: 가산점 (게이트 통과한 제품끼리만, 고민-성분 매칭)

- 사용자가 고른 "피부 고민"과 제품에 태깅된 "주력 고민"이 **몇 개 겹치는지 개수를 그대로 표시** (예: "고민 3개 중 2개 매칭"). 100점 만점 환산 안 하고, 매칭 개수가 많은 순으로 정렬.
- 데이터 방식: 제품마다 "주력 고민"을 수동 태깅 (제품 CSV의 `main_concerns` 컬럼, 위 6개 값 중 해당하는 것을 사람이 직접 보고 입력). 나중에 성분표 자동 분석 방식으로 전환 가능하도록 함수 인터페이스는 동일하게 유지.

### 3단계: 경고 문구 (점수와 무관, 참고용 표시만)

- `REGULATE_TYPE = "한도"`(배합 한도가 있는 성분) 포함 시 "배합 한도가 있는 성분이에요" 식 경고만 표시. 게이트 아님 — 제품 데이터에 실제 함량(%) 정보가 없어서 한도 초과 여부 자체를 판정할 수 없기 때문.

## 6. 데이터 소스

- **기피/금지 성분**: data.go.kr "식품의약품안전처_화장품 사용제한 원료정보" API (개발계정 자동승인, 하루 10,000건 무료). 필드: REGULATE_TYPE(금지/한도 등), INGR_STD_NAME, CAS_NO, COUNTRY_NAME, LIMIT_COND. 순서 정보·효능 정보는 없음 (순수 규제 데이터).
- **제품/성분 데이터**: 올리브영에서 수동으로 수집 (자동 크롤링은 이용약관상 하지 않기로 결정 — 사람이 직접 페이지를 보고 CSV에 옮겨 적는 방식). `data/ChaeInG_data - 통합.csv`가 현재 **최종 데이터**(2026-10-15 기준 105개 제품, 5개 카테고리 × 21개: 에센스/세럼/앰플, 스킨/토너, 로션, 크림, 미스트/오일). 선크림/클렌저는 미수집. 컬럼: `product_name, brand, category, skin_type_target, full_ingredients, source_url, 확인, main_concern`.
  - `main_concern` 컬럼은 **전부 비어 있음** → LLM 초안 생성 + 사람 검수로 채울 예정 (출력은 6개 고민 어휘로 제한)
  - `skin_type_target`은 105개 중 101개가 "모든 피부" → 변별력 없음
  - 이 CSV를 DB로 넣는 적재 스크립트는 아직 없음 (작성 예정)
- **고민-성분 매핑용 효능 데이터**: 아직 못 찾음 (미해결 — 이게 없어도 위 2단계처럼 "제품 단위 수동 태깅"으로 우회 중)
- **성분 효능/주의사항(`ingredients.efficacy`, `caution`)**: 식약처 사용제한 원료정보에는 규제 정보만 있고 효능 설명은 없음. 다른 공공 성분 API 존재 여부 조사 필요 (TBD)
